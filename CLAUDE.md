# CLAUDE.md — mecatl

A **headless agentic coding harness** in Go 1.26 (hexagonal/DDD): the streaming agent
loop, ~7 tools, permissions, hooks, and subagents behind a provider-agnostic port.
Driven over gRPC + HTTP; an optional Bubble Tea TUI (`mecatui`) is a client.

> `AGENTS.md` and `docs/harnesses/` are the **research corpus** this was built from, not
> harness conventions. For the build itself read `docs/architecture.md` (how it works),
> `docs/usage.md` (how to run it), and `docs/design/*` (rationale per feature — multi-provider,
> workspace-trust, soul, memory, agent-teams each have a doc there).
> `docs/design/IMPLEMENTATION-NOTES.md` holds the dense per-subsystem implementation/status
> detail. **Prefer adding design detail to those docs, not here** — this file is a lean
> correction file, not documentation.

## Commands

**Always build through the Taskfile** — a bare `go build` in the repo root drops stray
binaries and is the wrong workflow.

```sh
task build              # → bin/mecated, bin/mecademo, bin/mecatui  (NEVER `go build` to repo root)
task test               # full suite, -race
task test:golden        # refresh mecatui View/teatest goldens (-update) then re-run
task lint               # golangci-lint v2 + go vet
task generate           # regenerate contracts/gen from contracts/proto via buf
go test ./engine/agent/ -run TestFullCycle   # a single test
go run ./cmd/mecademo    # end-to-end demo, fully offline (mock provider)
```

## Architecture (where things live)

Layered DDD; the package's layer is in CAPS. Design rationale lives in `docs/design/`.

Top-level shape: `engine/` is the importable core — the domain packages, the port
interfaces, the agent loop, and the in-tree reference adapters (`engine/adapter/*`) —
fully self-contained (tests included: nothing under `engine/` imports `internal/...`)
and intended to be importable as a library by external consumers; `internal/` holds
the heavy adapters (`internal/adapter/*`) and the composition layer (`internal/app`).

- `engine/session/` — DOMAIN: the `Session` aggregate (state machine), Conversation, the `ToolCall`/`ToolResult`/`Usage` value objects, the `Event` taxonomy.
- `engine/governance/` — DOMAIN: permission `Effect`/`Scope`/`Rule` + `Evaluator`, bash splitting/canonicalization, hook event types. **Session-free** (`session` imports it, never the reverse).
- `engine/tool/` — DOMAIN: `Tool`/`ToolSpec`/`Catalog` **and** the `FileSystem`/`Workspace` interfaces (see gotcha).
- `engine/prompt/` — DOMAIN: two-layer prompt assembly + AGENTS.md/CLAUDE.md discovery; the turn-0 `InstructionAssembler` chain and its consumer-local ports (`MemoryIndexSource`, `SoulSource`, `UserModelSource`). Trust/provenance decisions live in composition, not here.
- `engine/port/` — the PORT interfaces the loop consumes (`LLMProvider`, `SessionStore`, `HookRunner`, `PermissionPolicy`, `Clock`, `Logger`, `EventSink`).
- `engine/agent/` — APPLICATION: the loop (`Engine`/`Run`), dispatch, permission pause/resume, compaction, the Subagent delegation tool, the agent-team `Supervisor`/`TeamTool`. Read-only subagents (Subagent + team members) run their Bash in an isolated git worktree via a sandboxed runner — see `docs/design/AGENT-TEAMS-SPIKE.md` and the subagent-shell gotcha.
- `engine/adapter/` — the REFERENCE adapters that travel with the importable core (offline tests + sane defaults for any engine consumer): `mockllm`, `memfs`, `memstore`, `sessnap`, `permpolicy`, `permstore`, `fsconformance`, `memconformance`. Stdlib + engine-only (memfs adds doublestar); strict depguard allowlists; core PRODUCTION code still must not import them (test files may).
- `internal/adapter/` — ADAPTERS: `openai`, `anthropic` (native Messages API), `osfs`, `permconfig`, `workspacetrust`, `soul`, `memory`, `providercatalog` (embedded models.dev subset), `openrouter`, `gitenv`, `hashutil`, `xdgconfig`, `hookexec`, `store/jsonlstore`, `tools`, `server`.
- `internal/app/` — COMPOSITION (not domain): the single shared assembly (`app.Build`) of provider registry + catalog + policy + engine into a `server.Service`. The ONLY package allowed to import adapters + `engine/agent`. Per-session provider/model routing, live model listing, capability intersection, trust/soul selection all live here. See `docs/design/MULTI-PROVIDER.md`.
- `contracts/proto/mecatl/v1/` — gRPC contract (source of truth); `contracts/gen/` is generated, **never hand-edit**.
- `cmd/mecated/` — standalone server (composition root): flags, TLS/auth/rate-limit, HTTP + metrics listeners. `cmd/mecademo/` — the offline demo.
- `cmd/mecatui/` — optional gRPC **client** TUI; by default hosts a `mecated` in-process over a UNIX socket. `ui`/`theme`/`client` import no `engine/...` or `internal/...` and no proto directly — they render from relayed proto `Event`s. See `docs/tui.md`.

## The layering rule (the thing to get right)

Dependencies point **inward only**, machine-enforced two ways (both run under `task lint`/`task test`): the **depguard allowlist** in `.golangci.yml` (per-file — each core tier is `list-mode: strict` allowing only `$gostd` + the exact core packages it imports, with an `os` deny on top; a NEW heavy-adapter import is rejected by default) AND the **DAG test** in `engine/arch/layering_test.go` (whole-graph — transitive direction + cycle detection, which the per-file depguard cannot express). `engine/team` is part of the core (agent imports it).

- Domain (`session`, `prompt`, `governance`, `tool`), `engine/team`, and `engine/agent` must **never** import an adapter, `contracts/gen`, `os`, the OpenAI/Anthropic SDKs, or gRPC.
- `engine/port` imports only domain + stdlib. `engine/agent` imports only domain + `port` + `team` (+ stdlib + `golang.org/x/sync/errgroup`) — adapters are injected. (Core **test** files may import the `engine/adapter/*` reference adapters — `memfs`/`mockllm`/`permpolicy`/… — to run offline; the depguard core rules exclude `$test`, and the DAG test reads non-test imports only. The engine tree is fully self-contained, tests included: nothing under `engine/` imports `internal/...` — integration tests that need a heavy adapter live next to that adapter under `internal/adapter/`.)
- Concrete adapters meet ports **only** in the composition layer — `internal/app` and the `cmd/` mains. No DI framework; explicit constructors. Keep wiring in `internal/app`, not in domain/`port`/`agent`.

## Things That Will Bite You

- **`FileSystem`/`Workspace` live in `engine/tool`, NOT `engine/port`.** Moving them to `port` creates a `port↔tool` cycle (`port.LLMRequest` references `tool.ToolSpec`; `Tool.Execute` takes a `Workspace`). Leave them in `tool`. The osfs Workspace also carries per-skill READ-ONLY allowed roots (`osfs.WithReadRoots`, fed from `catalogAssets.skillReadRoots`) so Read/Stat — never Write/Glob/Grep — serve an activated skill's out-of-workspace files by absolute path; don't strip the option from the workspace factory/fork constructors or out-of-workspace skills regress to unreadable.
- **`port.PermissionPolicy` is implemented in `engine/adapter/permpolicy`, not `governance`** — `governance` can't import `session` (cycle), so the session-aware policy is an adapter over the session-free `governance.Evaluator`.
- **Preserve these invariants — they have tests that fail if you regress them:**
  - Edit's three invariants: read-before-edit (+ unchanged-since), exact match, uniqueness-unless-`replace_all`.
  - Dispatch is **read-parallel / mutate-serial** (`tool.ReadOnly()` drives it). Two mutating tools must never run concurrently.
  - Permissions resolve **deny-dominant**: a deny in ANY scope is absolute. Among ask/allow the higher *configured* scope wins, with ONE narrow exception: a higher-scope config Allow may loosen **only** the built-in-default Ask (the `ScopeBuiltinDefault` floor) — it must NEVER suppress a *configured* Ask. Equal-scope ask/allow ties favor Ask. Plan mode hard-denies mutations first. The six memory tools + the synthetic `soul:apply` action are floor-scoped (`ScopeBuiltinDefault`) Allows — pre-approved but config-overridable; they loosen no other tool's Ask. (Scope order high→low: `Managed > CLI > LocalProject > SharedProject > User > ScopeBuiltinDefault`.)
  - The bash gate must stay substitution/newline-aware (`$()`, backticks, subshells, `\n` fail safe). Don't simplify `SplitCommands`/`ReadOnlyBash` to operator-only splitting.
- **Subagent Bash permission asks resolve in a 4-step model — do NOT collapse it to a blanket auto-deny.** (1) **A1 read-only substitution** (`governance.SubstitutionReadOnly`): a substitution/subshell segment whose every recursively-extracted inner is read-only AND whose blanked outer is read-only resolves by the ordinary rule fold instead of flooring at Ask — GLOBAL (main + children). It is a SEPARATE classifier: `ReadOnlyBash`/`simpleReadOnly`/plan-mode and `FuzzReadOnlyBash`/`FuzzSplitCommands` Inv-5 stay byte-for-byte UNCHANGED. (2) **A2 isolation auto-approve** (`governance.IsolationApprovable`): an ISOLATED subagent (worktree/force-copy fork) auto-APPROVES read-only ∪ a MINIMAL worktree-safe verb set `{go test,build,vet,list}`, minus worktree-escape verbs (`git push/config/remote/fetch/pull/clone/worktree/submodule`); fail-safe false on any ambiguity. It resolves the REAL git subcommand PAST leading global flags — a path-bearing `git -C`/`--git-dir`/`--work-tree` escapes the worktree ⇒ NOT approvable (`gitSubcommand`) — and REJECTS go build/test flags that run an arbitrary EXTERNAL program (`-exec`/`-toolexec`/`-overlay`: the worktree isolates the FS, not the process; `goArgsRunExternalProgram`). `FuzzIsolationApprovable` asserts POSITIVE soundness (every cleared segment is scaffolding/read-only/worktree-safe-go-no-exec), mirroring `FuzzSubstitutionReadOnly`. (3) **Surface to human**: when steps 1-2 don't resolve AND the parent run is interactive (`Deps.Interactive`, an interactive parent installs `Run.childAsks` = `childAskRouter`), the child's ask is register-then-emit SURFACED as a real parent `EvPermissionAsk` (command CLAMPed via `clampPreview`, framed as a subagent request, raw args NOT forwarded — gauntlet #7 holds); the parent's `Run.Approve` routes the verdict to the child via the child-namespaced askID (NO proto change — the child session id IS the namespace). The child parks in its own goroutine; concurrent team members keep running (supervisor's per-member errgroup). (4) **Headless** (no router) → auto-deny with the ACCURATE model-facing message (`childAutoDenyMessage`: "not permitted in a non-interactive subagent shell: …", carried via `approval.denyReason`, NOT "denied by user") PLUS a correlated operator diagnostic (`LevelInfo`, `agent=<role>`), never a parent-stream content event. `--yolo` (`Config.AllowAllTools`) ALSO loosens the substitution floor for the MAIN agent (`governance.WithLooseSubstitution`, threaded via `mainEvaluatorOptions`); a configured Deny/Ask in any scope still wins. Resolution lives in `governance` (steps 1-2) + `agent` (`resolveChildAsk`, `childPosture`, steps 3-4) + composition (`Deps.Interactive`); no adapter/proto/server type crosses into `agent`.
- **No stdio MCP, ever.** Future MCP is **streaming-HTTP transport only**. Never spawn `os/exec` MCP servers. (mecatl itself never speaks stdio; ToolHive stdio backends are HTTP-proxied and fine.)
- **ACP prompt content is multimodal + capability-gated.** Every block becomes text, a `session.Content` Part, or a loud `codeInvalidParams` — never silent-drop. Reuses `session.NewContent`/`ValidateMediaParts` (no second validation path); image/audio gated on `Service.ProviderCapabilities()`. Audio is wired but dormant (OpenAI Responses has no audio input).
- **Capability truth is a SINGLE composition-computed intersection.** `internal/app/capability.go`'s `modelCapability` = (per-model modalities) ∩ (adapter `Capabilities()`). The modality input is **LIVE-FIRST** (`reg.meta.modalitiesFor` — the SAME live `InputModalities` the picker's `projectModelEntry` reads) with a catalog floor then adapter-only passthrough, NOT catalog-only — don't "simplify" the live read away or the session echo and picker diverge (an OpenRouter text-only model on the shared openai adapter would falsely report `image:true`). The one neutral value feeds ListModels, the `CreateSessionResponse` echo, and the ACP gate — don't recompute it per sink or they'll disagree. Details: `docs/design/MULTI-PROVIDER.md`.
- **Tests are offline.** Use `engine/adapter/mockllm` + `engine/adapter/memfs`; never hit a live model/network. The OpenAI/Anthropic SSE→Chunk paths are tested from fixtures.
- **The LLM adapters are stateless** (`store:false`, full replay each turn, byte-stable prompt prefix for caching). Don't switch to server-side conversation state. `port.LLMRequest` is **provider-neutral and must stay so** — `Model` is a bare opaque string; provider-private knobs (reasoning-effort, thinking-budget, store/include) are adapter-construction Options, NOT new `LLMRequest` fields (a guard test in `port/llm_neutral_test.go` tripwires silent widening). `Message.Reasoning` carries one opaque replay blob per message — structure neutral, contents provider-private; don't widen it.
- **Provider is FIXED per session.** A per-session engine re-derives ALL provider-closing Deps via `engineDepsForProvider` (LLM, Compactor, Model, TokenCounter, prompt model, context window) — never clone-and-swap-LLM, or it compacts/counts through the wrong model.
- **Per-session/selector catalogs are assembled by the SAME `assembleCatalog` as the shared one** (`internal/app/catalog.go`; issue #42 — the THIRD firing of the per-session-drift class, so the fix is structural: ONE registration path, no second list to forget). Phase A (`buildCatalog`) builds the process-wide `catalogAssets` once — the shared global MCP manager (reused-not-reconnected; a selector session must NOT silently strip github/slack/fetch/etc.), the `tool.MemoryStore` pair (interface-threaded; the flocked `memory.New` calls in `buildCatalog`/`buildUserModelStore` remain the sole construction sites, never re-opened per session), the resolved skills, the ONE process-wide preserved-fork LRU — and `sessionEngineFactory` assembles every per-session catalog over them: core + global MCP (+ the `MCPResourceTools` meta-tools) + client MCP + Subagent trio + Parallel + Team + the six memory tools + Skill/SkillDraft (that order; global-wins on collision). The ONLY sanctioned per-session deltas: the client MCP tools, and the unwrapped hooks (`maybeWrapUserModelReview` is main-engine-only) — guarded by `TestPerSessionCatalogMatchesSharedCatalog` (exact tool-name-set equality). The shared `globalMgr` is owned by `Build`: its `Close` is NEVER folded into the per-session `SessionEngineResult.Close` (a per-session `CloseSession` closing it kills MCP for all other sessions); `globalMgr` is also the `reference:`-resolution mainMgr for per-session subagents.
- **Mid-stream stalls are bounded by `llmresilience.StreamIdleTimeout` (default 120s), NOT `PerAttemptTimeout`.** Post-first-chunk idle gaps get a per-chunk watchdog that synthesizes a terminal `*StreamIdleError` (`errors.Is(_, context.DeadlineExceeded)`) — the openai/anthropic adapters SWALLOW the ctx error on cancel (yield nothing), so the wrapper MUST synthesize it. The stall is TERMINAL, never retried (no-replay-after-first-chunk holds). Pre-first-chunk stalls stay on `PerAttemptTimeout`+retry, unchanged. It's a `Config` Option threaded through composition — NOT a new `port.LLMRequest` field.
- **`Session` is an aggregate** — mutate it through its methods (`RecordUserPrompt`, `RecordAssistant`, `ReplaceHistory`, …), not by poking `Conversation` directly.
- **Compaction must NEVER emit unpaired history.** Both compactors snap the kept-tail boundary past leading tool results (`snapCutToTurnBoundary`) so the tail never starts on a `RoleTool` orphan whose call was dropped, then self-validate with `session.ValidateToolPairing` (bidirectional) and **abort to the original history** on failure (`agent.ErrCompactionWouldOrphan`, handled in `maybeCompact` reusing the existing compaction-fail WARN — do NOT add a diagnostics line). `Session.ReplaceHistory` rejects unpaired slices too. Why it matters: an orphaned tool result → provider HTTP 400 → `failed`, which is UNRECOVERABLE; the fix removes the trigger (failed-recoverability stays deferred).
- **Every run-entry path must reopen-if-completed OR interrupt-if-cancelled.** A turn drives the session to a terminal state within one `Engine.Run`; the engine does NOT recover it. Any path handing a *reused* session to `Run`/`RunContent` must recover the terminal state first or `RecordUserPrompt` rejects it. `completed → Reopen → idle`; `cancelled → Interrupt → idle` (Interrupt also history-repairs: it closes out tool calls orphaned by a mid-dispatch cancel with synthetic error results, so the replay has no dangling `tool_use`/`function_call`). `Reopen` stays completed-only; a `failed` session is NOT resumable and still surfaces the illegal transition. In the service layer: **`loadAndReopen`, never `GetSession`, before a run** — it drives the right seam per state (`GetSession` is read-only snapshots). All wire surfaces funnel through `Service.StartRunContent`, which routes through `loadAndReopen`. Guarded by `TestStartRunContentReopensCompletedSession` + `TestStartRunContentRecoversCancelledSession`.
- **The Team tool returns the LEAD's consolidated synthesis** (a final synthesis turn in `Supervisor.Run`, output on `TeamOutcome.Report`), NOT concatenated member `LastText` (that is the degraded `joinTeamFallback` only). Synthesis reads three fenced-UNTRUSTED layers: the findings ledger (members append via `RecordFinding`) + a LastText/completed-task digest for non-recording members + the lead's inbox. **The team GOAL is TRUSTED by default** — rendered as the member's/lead's genuine instruction (plain, NOT inside an `<<<UNTRUSTED` fence) in both `renderTurnPrompt` and `buildSynthesisSources`, because its provenance is the principal (`WithTeamGoal` is the sole writer; no member tool can mutate it). It is still `neutraliseFraming`'d so it can't forge a fence/header. Peer message bodies + claimed-task descriptions stay fenced. Don't silently re-fence the goal: a relay/multi-tenant deployment opts INTO untrusted via `agent.WithUntrustedGoal(true)` (gRPC: `server.Config.TeamGoalUntrusted`; the in-loop Team tool is always trusted). Member sessions persist via `WithMemberStore` under `MemberSessionID(teamID, member)` = `team-<teamID>-<member>` (the SINGLE id-scheme source the supervisor save AND the PULL `InspectMember` tool share — don't let them drift; collision-free across concurrent teams). A budget-stopped lead is still resumable (`memberRT.nonResumable` is set only on `StopError`/`Reopen`-fail) so the one synthesis turn still runs. `EvTeamFindings` mirrors `EvTeamTasks` end-to-end (session → proto `TeamFinding` → mecatui) — don't half-wire it. Both entry points (Team tool + gRPC `RunTeam`) share synthesis because it lives in `Run`. **The Team ToolResult MUST surface the team id** (`renderTeamResult` prepends a `Team id: <id>` line, BOTH on the synthesis-report and the `joinTeamFallback` path) — the id otherwise rides only the client-only `EvTeamStart` event, so without it the parent MODEL can never discover the id `InspectMember` requires. Render it VERBATIM (the published Team call id) per the `MemberSessionID` contract. The gRPC `RunTeam` consumer already holds the id (from `CreateTeam`/`EvTeamStart`), so the header is the in-process-tool fix only.

- **A completed turn with NO tool call AND no meaningful text is NUDGED, never silently ended.** A reasoning model can emit a "done" turn carrying only a reasoning blob (`text==""`, `calls==nil`). The loop (Step 5, `finishTurnNoTools`) injects a BOUNDED continuation user message (`noProgressNudgeText`) up to `Deps.MaxNoProgressNudges` times (`Config.MaxNoProgressNudges` → composition; default 2 applied in `NewEngine`; `<0` disables), emits a visible `EvNoProgress` event each time, and on exhaustion terminates CLEANLY via the completed path with `StopNoProgress` (a NON-error terminal → session ends `completed`, stays Reopen-recoverable) — NEVER an infinite loop, NEVER a silent `StopEndTurn`. The empty assistant turn IS recorded first (so its reasoning blob replays across the nudge); the nudge loop is ALSO bounded by `Limits.MaxTurns` (each nudged turn goes through `BeginTurn`). **The nudge fires ONLY on a BENIGN end** (`streamStop ∈ {StopEndTurn, StopNone}`): both adapters' `mapStop` relay a REAL terminal condition (`max_tokens`/`refusal`/`incomplete`/`failed`→`StopError`, `cancelled`→`StopCancelled`, limits) on the ChunkDone stop, NOT as a Go error, and a truncated/refused turn can also be empty — `finishTurnNoTools` surfaces that reason verbatim (StopError→`terminate`, else `terminateComplete`) BEFORE the no-progress branch, so a real terminal is never nudged or relabeled `StopNoProgress` (masking it would be the same silent-mislabel bug). **No `tool_choice` forcing** to fix this: forcing tool use is incompatible with Anthropic extended thinking and our OpenAI reasoning path — the fix is the bounded-nudge + per-model persistence prompt (`agencyDelta`), both provider-agnostic, never a `port.LLMRequest` field. `EvNoProgress` is an EVENT (transient status line in mecatui, like `EvCompaction`), NOT a diagnostics line (the "loop emits exactly THREE lines" invariant holds). Works for the SHARED engine: main + Subagent + Parallel + team member + lead synthesis (a no-progress synthesis is driven to a real report, not a skeleton). `EvNoProgress`/`StopNoProgress` are STRING passthroughs on the wire (proto `type`/`stop` are strings, not enums — no `task generate` needed). Unknown tool calls also get an `EvToolCall` card BEFORE the error result (card-before-the-gate holds for the unknown-tool path too).

- **The token budget is a turn-boundary CLEAN terminal (`StopBudget`), a Deps/Config knob — NOT an `LLMRequest` field.** `Deps.MaxRunTokens` (0 = disabled; `Config.MaxRunTokens` → `--max-run-tokens`) is the SHARED loop-level cumulative token ceiling, checked in `Engine.drive` Step 2 (before `BeginTurn`, after the `StopReason`/`ctx` checks) against the run's accumulated `session.Usage` via `Usage.TotalTokens()` (input+output; cache tokens EXCLUDED — `CacheReadTokens` ⊂ `InputTokens`). On crossing it ends via `terminateComplete(…, session.StopBudget, …)` — a NON-error terminal → `completed`, Reopen-recoverable, mirroring `StopNoProgress` exactly. The BOUNDARY check (never mid-stream) means an in-flight turn always completes (no-replay-after-first-chunk holds; an overshoot turn finishes, then the budget trips before the next turn). It is INHERITED by every engine (`childEngineDepsForProvider` delegates to `engineDepsForProvider` and does NOT clear it), so main + Subagent + team member + lead synthesis + Parallel all carry it; a per-call override may only TIGHTEN it. `StopBudget = "budget"` is a STRING passthrough (no proto enum). It surfaces via the `EvResult.Stop` taxonomy, NOT a new diagnostics line (the "loop emits exactly THREE lines" invariant holds). This is the PER-ENGINE half of the AGENT-TEAMS-SPIKE "Deferred 4A" brake, landed once for all delegation paths. The team-AGGREGATE half now exists too: `Supervisor.WithTeamTokenBudget` (`Config.MaxTeamTokens` → `--max-team-tokens`; `server.Config.TeamTokenBudget` for gRPC CreateTeam; per-call Team `max_team_tokens` TIGHTEN-only) is a supervisor-level ceiling checked at the ROUND boundary BEFORE `planRound` (so the in-flight round + the lead's synthesis still complete; members are NOT individually stopped), accumulating each member's per-drive `EvResult.Usage` onto `memberRT.tokensUsed` (NEVER also `turn.end` — double-count) and surfacing via `TeamOutcome.BudgetExhausted`/`Usage` + `teamStop`→`StopBudget` (when `!Quiescent`).

- **Subagent fan-out is bounded by the child concurrency gate for ALL children — forking AND forker-less.** `SubagentTool.childGate` (default `defaultMaxConcurrentChildren = 4`, `WithMaxConcurrentChildren`; old `WithMaxConcurrentSubagentShells` is a deprecated alias) is acquired at the TOP of `run()`, not only on the worktree-forking path — Subagent is read-only so the dispatcher fans out N concurrent Subagent calls per turn and each consumes a child session + an LLM slot. The team supervisor's round was ALREADY bounded (`errgroup.SetLimit(s.concurrency)`, `WithTeamConcurrency`, default 4) — don't add a redundant bound, and don't drop `SetLimit` (guarded by `TestSupervisorRoundConcurrencyBounded`). read-parallel/mutate-serial is UNCHANGED (the gate bounds child START, not dispatch ordering). Per-call `subagentArgs.MaxTurns`/`MaxToolCalls`/`TimeoutMs` are OPTIONAL pointers, TIGHTEN-ONLY (`tightenLimit` may only lower `session.Limits`, never raise — the model can't escape the operator's bound) + a `context.WithTimeout`; domain-only, NO wire/proto change. **`background: true` detaches a Subagent child, RUN-scoped:** the call returns the immediate started-result (agentId trailer FIRST line); a goroutine owns fork→drive→persist→`markDoneResult`; the result BODY's SOLE channel is the read-only `SubagentStatus` tool (roster/poll + `wait_ms` park, capped 120s; reads `parentCaps.children`; registered wherever Subagent is, never in child catalogs — distinct from InspectSubagent's persisted cross-run transcripts). Background gate acquisition is FAIL-FAST (the error lists live background ids, ids ONLY — abort BEFORE the ids read, or it lists the failing call's own id) while foreground stays blocking. At run end `drainChildren` (TOP of both terminate paths) cancels+joins live background children in TWO phases — `childDrainCap` (10s), then `abortEmits()` + `childDrainGrace` (1s) so a child parked in its own end-emit (consumer backpressure) JOINS instead of being misreported — then seals the registry: ALL child emits route through `safeEmit` (a post-seal emit is a no-op, never a panic; emitAbort closes BEFORE emitMu or seal deadlocks — pinned by `TestSealUnblocksEmitParkedSend`), and only a still-unjoined child is the ONE abandon WARN (the third diagnostics line); a cancelled child's still-pending surfaced asks are retracted at its registry terminal (`markDoneResult`, pre-doneCh-close ⇒ pre-seal ⇒ before `EvResult`; abandoned children get a pre-seal drain sweep; each retract is gated on `childAskRouter.unregister`'s answered-vs-pending bool, so an answered ask never draws a spurious retract). **Every guarded send on the run gives up when the seal's abort closes OR the run's `hardAbort` fires** — `Run.Cancel` arms `hardAbort` (a `hardAbortGrace`=1s timer, armed BEFORE the ctx cancel): the explicit unwedge signal, DISTINCT from the registry's `emitAbort` (seal-time, reachable only from the terminate paths) and from ctx (a cancelled run with a DRAINING consumer still delivers in-flight events incl. the terminal `EvResult` — that rationale is preserved TWO ways: the try-send-first shape in `emit`/`emitOrAbort`/the supervisor's member→evCh forward gives deterministic delivery while the buffer has room — a bare two-arm select would RANDOMLY drop post-cancel events — and the GRACE lets a merely-BACKLOGGED consumer absorb the tail before parked sends give up; once fired it is sticky, so the unwedge cost is paid once per run, never per event). Without it a consumer that stops draining wedges the run PERMANENTLY (the terminate paths that seal are themselves blocked behind the parked sends) — pinned by `TestCancelUnwedgesStalledTeamRun`. Both relays (gRPC `Converse` + HTTP SSE) are drain-to-discard after the FIRST Send/Write error: record the error, `run.Cancel()`, keep ranging `run.Events()` discarding until close (no further writes, no `EvPermissionAsk` Persist on the error path), then (gRPC only — the SSE handler returns nothing) return the recorded error — never stop draining on a send error or a busy run wedges in its own emits after the client dies. A run-end-cancelled background child persists and is resumable. Pre-start failures REMOVE the registry entry (never a done+StopNone phantom; a failed RESUME attempt reinstates the displaced prior terminal + its undelivered result); a cancel-while-queued keeps a meaningful StopCancelled entry; a never-driven team member is removed at cleanupAll. **Completion delivery is notice + nudge, both EVENT-SILENT ordinary recorded history (A2/A9/D10):** every turn boundary (drive Step 2a, BEFORE `preTurnTerminal`) announces newly-finished background children in ONE harness-note user message — ids + stop labels ONLY, nothing child-authored; the registry `noticed` flag is SEPARATE from `delivered` (never re-noticed, still collectible; an already-collected result is noticed silently, not listed) and `e.save` runs right after the record (replay-durable). A would-be CLEAN end (meaningful text, benign stop) with LIVE background children is deferred ONCE per run by the background-pending nudge (`finishTurnNoTools`, ids only) — it MUST stay before the clean-terminal calls (`drainChildren` at their top has already cancelled+sealed), never fires on the no-progress/empty-turn path or any non-clean terminal, never relabels the eventual stop, and emits NO `EvNoProgress`; the second clean end terminates normally and the drain cancels+persists what is left.

- **Subagent per-call `model` override re-derives via the engine FACTORY, never clone-and-swap.** `subagentArgs.Model` mints the override child through `WithSubagentEngineFactory` (a composition closure `func(model string)(*Engine,bool)` built by `buildSubagentEngineFactory` over `newChildEngineForProvider`), so Compactor/TokenCounter/`Env.Model`/ContextWindow are RE-DERIVED for the override model — the same "Provider is FIXED per session" discipline. `agent` + `model` together is REJECTED (a specialist already pins its model). None widen `port.LLMRequest`.

- **Subagent structured output is bounded validation-retry, NOT `tool_choice` forcing; the agentId is in the RESULT TEXT.** `subagentArgs.OutputSchema` gives the child a synthetic `SubmitResult` tool (injected run-scoped via `RunOptions.ExtraTools`, never registered into the shared catalog) whose params ARE the schema; the child is PROMPTED to call it (no `tool_choice` — incompatible with Anthropic thinking + the OpenAI reasoning path). `SubmitResult.Execute` validates via `session.ValidateJSON` (a JSON-schema SUBSET validator, FAIL-OPEN on unsupported keywords — the SINGLE structured-output choke point, DISTINCT from `ValidateMediaParts`); on a miss the Subagent tool re-injects a correction and re-drives the SAME child (`session.Reopen`) up to `defaultStructuredOutputRetries` (2), then ends with the new `session.StopStructuredOutput` CLEAN terminal rendered as a MODEL-VISIBLE validation-error tool result (never only a log line). Default (no `output_schema`) = free-text, unchanged. **Per-attempt vs cross-attempt limits:** each correction re-drive `Reopen()`s the child, which RESETS its `Counters`, so per-call `MaxTurns`/`MaxToolCalls` (and `WithChildLimits`) bound EACH ATTEMPT — a structured-output child can use up to `(1+defaultStructuredOutputRetries)×` its turn/tool budget across the whole call (bounded, not a runaway).
